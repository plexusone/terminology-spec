# v0.2.0

**Release date:** 2026-11-13

Terms can now carry their pronunciation in the International Phonetic
Alphabet (IPA), per locale, beside the respelling in `pronunciations`.

## Highlights

- **IPA pronunciations.** A TTS provider that accepts phonemes, through SSML
  `<phoneme alphabet="ipa">` or a PLS lexicon, says a name exactly as written
  in IPA. Providers and models that read text only keep using the respelling.

## Added

- `Term.IPA` (`ipa` in JSON) maps a BCP-47 locale to the term's IPA, without
  slashes or brackets:

  ```json
  {
    "id": "lamborghini",
    "canonicalForm": "Lamborghini",
    "pronunciations": {"en-US": "lambor gheeny"},
    "ipa": {"en-US": "lamborˈɡiːni"}
  }
  ```

- `ExportIPAProfile(terms)` projects terms into term → locale → IPA, the
  phoneme counterpart of `ExportPronunciationProfile`. `CanonicalForm` and
  every alias become keys for the same table.
- The `ipa` property in `schema/terminology.schema.json`.

## Upgrading

The field is optional, so existing term files and code are unaffected. Add
`ipa` to terms whose respellings don't sound right. Keep the respelling too:
it's what providers without phoneme support say.

## Consumers

- [omnivoice-core](https://github.com/plexusone/omnivoice-core) v0.19.0
  turns terms into per-request pronunciations with `PronunciationsFor`, and
  providers choose between the IPA and the respelling.
