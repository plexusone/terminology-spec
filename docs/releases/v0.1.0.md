# v0.1.0

**Release date:** 2026-07-26

Initial release of terminology-spec — the canonical term IR for consistent
handling of proper nouns, acronyms, and standard names across TTS
pronunciation, subtitle case-correction, multi-language narration, and UI
strings.

## Highlights

- **Single source of truth** for term pronunciation, casing, and translation
  across videoascode, omnivoice-core, presentation decks, and product surfaces
- **247 embedded terms** available as a Go dependency with no filesystem access
- **Export functions** for pronunciation profiles, case dictionaries, and
  translation maps

## Added

### Core types

- `Term` struct with `id`, `canonicalForm`, `aliases`, `category`, `scope`,
  `tags`, `context`, `pronunciations`, and `translations` fields
- `TranslationPolicy` enum: `preserve`, `translate`, `transliterate`,
  `localized-name`, `context-dependent`
- `TranslationEntry` struct for per-locale translation overrides

### Embedded term sets

- **Builtin** (~237 terms): generic industry-tech terms for case-correction —
  AI/ML, companies, dev tools, programming languages, frameworks, cloud/infra
- **Curated** (~10 terms): hand-authored canonical terms with real
  pronunciation and translation data — AAuth, OAuth, AI, app, IETF standards

### Term loading

- `Builtin()` — load embedded generic-industry terms
- `Curated()` — load embedded hand-authored canonical terms
- `All()` — Builtin merged with Curated (Curated wins on ID collision)
- `LoadDir(path)` — load terms from a project's own `terms/` directory
- `LoadFS(fs, path)` — load terms from an embedded filesystem

### Export functions

- `ExportPronunciationProfile(terms)` — term → locale → spoken form for TTS
- `ExportCaseDictionary(terms)` — lowercase alias → canonical form for subtitles
- `ExportTranslationMap(terms, locale)` — canonical form → translated form

### Utilities

- `Merge(base, overlay)` — merge term sets with overlay winning on ID collision
- `Filter(terms, predicate)` — filter terms by category, scope, tags, etc.

### Schema

- JSON schema at `schema/terminology.schema.json` generated from Go types
- `schema-gen` command for regenerating the schema

## Consumers

- [omnivoice-core](https://github.com/plexusone/omnivoice-core) `terminology`
  package wraps this spec with `Pronouncer` and `CaseCorrector` engines
- [videoascode](https://github.com/grokify/videoascode) consumes via
  omnivoice-core for TTS pronunciation and subtitle case-correction
